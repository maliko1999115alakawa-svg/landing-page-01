# ランディングページ制作課題

Figmaデザイン（LP_pc_2）をコーディングしたランディングページ。
ビルド不要の素の HTML / CSS / JavaScript で構成しているので、`index.html` をブラウザで開けばそのまま表示できる。

## ディレクトリ構成

```
landing-page-01/
├── index.html
├── contact.html        お問い合わせフォームの仮ページ（下記「公開前の確認事項」参照）
├── server.py           キャッシュ無効化ローカル開発サーバー（開発時のみ使用）
├── css/
│   ├── base/           土台。ここだけは必ず最初に読み込む
│   │   ├── reset.css       ブラウザ既定スタイルの打ち消し
│   │   ├── variables.css   デザイントークン（色・書体・余白・ブレークポイント）
│   │   └── base.css        body やユーティリティの既定スタイル
│   ├── layout/         ページ全体の骨格
│   │   ├── container.css   コンテンツ幅とセクション境界の三角シェイプ
│   │   ├── header.css
│   │   └── footer.css
│   ├── components/     複数セクションで使い回す部品
│   │   ├── button.css
│   │   └── section-title.css
│   └── sections/       セクション1つにつき1ファイル
│       ├── hero.css / worry.css / solve.css / support.css / flow.css
│       └── plan.css / trainer.css / faq.css / schedule.css / cta.css / recruit.css
├── images/             セクション名でフォルダ分け
└── js/script.js        本体の挙動（ハンバーガー／カルーセル／FAQ／試験日程）
```

CSS は **土台 → レイアウト → 部品 → セクション** の順に `<link>` で読み込んでいる。
後から読むファイルほど具体的な指定になるので、詳細度を上げずに上書きできる。

## 設計の方針

- **命名は BEM**（`block__element--modifier`）。
- **色とサイズは `css/base/variables.css` に集約**。ブランドカラーの変更などは原則このファイルだけを触ればOK.
- **セクションを増やすときは `css/sections/` にファイルを1つ足して `index.html` から読み込む**。既存ファイルには手を入れない。
- `js/script.js` は4つの挙動（ハンバーガー／講師カルーセル／FAQ／試験日程の表示切り替え）を担当。
  FAQ は `<details>` で組んであるため、**JS が動かなくても開閉と内容の閲覧はできる**。

## レスポンシブ

| 幅 | 挙動 |
| --- | --- |
| 1101px 以上 | PCカンプ（1440px）どおりの配置 |
| 768〜1100px | PCと同じ構成（ヒーローの写真＋シェイプの重ね方など）を維持したまま、比率で縮小。カード列は2列に。文字サイズだけは縮みすぎないよう下限を設けている |
| 767px 以下 | SPカンプ（402px）に合わせた1列レイアウト。ナビはハンバーガー、講師紹介は横スクロールカルーセルに切り替え |

## デザインとの差分・判断したところ

作業中に判断が必要だった点を残しておく。

1. **「ご利用の流れ」の循環図** — 矢印・人物・楕円は Figma のパスをそのまま `flow-art.svg` に書き出し、
   文字は HTML で重ねている。図版を1枚絵にしていないので、拡大しても文字が潰れず、読み上げ・検索にも残る。
   SPでは縮小すると図中の文字が読めなくなるため、横スクロールで原寸に近い大きさを保つようにした。
   なお、カンプでは「2 講師とマッチ」のラベルだけ枠に収まらず文字あふれを起こしていたため、
   実装では文字を少し詰めて楕円の中に収めている。
2. **FAQ の2問目・3問目の回答** — カンプでは閉じた状態で、回答文が入っていなかった。
   アコーディオンとして成立させるよう回答文を作成して入れてある。
3. **試験日程のカード枚数** — PCカンプは第32回・第33回の2枚、SPカンプは第34回を加えた3枚だった。
   今回はPCカンプに合わせて2枚にしている。
   なお開閉は `<details>` を JS（`initSchedule`）で制御しており、PC・タブレットでは常に両方開いた状態、
   SPのみFAQと同様に1枚だけ開く排他アコーディオンにしている（JSが動かない場合も両方開いた状態で読める）。
4. **講師紹介** — PC・タブレット・SP共通の1本のカルーセル（矢印ボタン・スワイプ操作に対応、端でループ）で、
   一度に見える枚数だけ幅で切り替えている（PC：3枚／タブレット768〜1100px：2枚／SP：1枚）。
   カード自体の枚数・内容はPCカンプの3枚のまま変えていない。
5. **背景の粒状ノイズ** — カンプの「ベースエフェクト（NOISE）」は再現していない。
   各セクションの背景は、ノイズを除いた状態の色を実測してベタ塗りで指定している。

## イラスト素材について

写真は Figma の元画像をそのまま使用。イラストは **Figma 上のパスをそのまま SVG に書き出している**
（`worry-man.svg` / `worry-woman.svg` / `flow-art.svg` / `cta-illust.svg` など）。書き出し画像を切り抜いたものではないため、
輪郭が滲まず、拡大しても劣化しない。

Figma のイラストは数十〜数百個のパスに分かれていて1枚のSVGとしては取得できないので、
各パスとその配置情報を取得し、スクリプトで1枚のSVGに組み直している。
反転・回転・マスク・クリップ・乗算合成もそのまま移している。

合成したSVGは1点ずつ Figma の書き出しと重ねて確認済み。ただし次の2点だけ扱いを変えている。

- **「まずはご登録」の吹き出しの尻尾** — 回転の解釈が合わなかったため SVG から外し、CSS の三角形で描いている。
- **お悩みセクションの紙テクスチャ** — SVG を `<img>` や `background-image` として使うと外部ファイルを
  読み込めないため、縮小・JPEG圧縮したうえで data URI として埋め込んでいる（`worry-blob.svg` 全体で 28KB）。

## 動作確認

- Chrome（headless）で PC 1440px / SP 402px を描画し、Figma の書き出しと重ねて検証済み。
  セクションの高さは全体 10,898px に対して誤差 90px 以内。
  （SP は Chrome のウィンドウ最小幅が 500px のため、402px の iframe 越しに確認している）
- 合成した各SVGは、Figma が書き出した同じノードの画像と1点ずつ重ねて差分を確認済み。
- JavaScript の4機能（FAQ の排他開閉、講師カルーセルの送りと端でのループ、ハンバーガーの開閉と `aria-expanded`、
  試験日程アコーディオンのPC常時展開／SP排他開閉の切り替え）はブラウザ上で動作を確認済み。

## 公開前の確認事項

以下は制作課題を進める中で用意した、本番公開前に見直す必要があるファイル・仕組み。

- **`contact.html`（お問い合わせページ）** — 各セクションの「お問い合わせ」導線の遷移先として置いている仮ページ。
  実際のフォーム機能（送信処理）は実装していないため、公開前に本物のフォーム（外部サービス連携など）へ差し替えが必要。
- **`server.py`（開発用ローカルサーバー）** — `python3 server.py` で起動する、キャッシュを無効化するだけの
  簡易 HTTP サーバー。CSS/JS の変更をブラウザにすぐ反映させるための開発補助ツールで、本番のホスティングには使わない。
- **`index.html` の `<meta http-equiv="Cache-Control">` 系タグと、CSS `<link>` の `?v=` クエリ** —
  開発中にブラウザキャッシュを避けるために付けたもの。公開時は削除して通常のキャッシュを効かせる想定。
- **`images/ogp.jpg`** — OGP用の画像が未用意。SNSシェア対応が必要なら差し替える。
